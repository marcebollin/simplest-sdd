# Examples

These examples show an earlier version of the framework. Keep them unchanged as history. The current [init prompt](../prompts/init.md) and [update prompt](../prompts/update.md) describe the 0.18.0 guidance. It uses compact HTML designed for the reader and content, with clear state, small meaningful groups, useful visuals, and purposeful reading controls. Explanations use natural prose. ASD-STE100 principles complement structured action lists, acceptance criteria, and checklists.

Changes stay visible until they have approval and their implementation is complete and verified. Existing authorization for a change to an owning spec counts. The marks do not add an approval gate. Existing content divisions remain in place. Convert an old spec's presentation only when a task revises that spec.

- [Read-later request-refinement conversation](discovery-conversation.md): an anonymized example of the mandatory five-question discovery round with visible questions and an explicit request for the user’s answers, a consequential reuse choice, automatic existing-spec updates, and new-spec selection while preserving actual user answers and approvals for the same unchanged scope on resume.
- [Read-later generated result](generated-result.md): concise `AGENTS.md` routing and a short skill entrypoint that both retain the explicit question gate and visible spec-reporting reminder, with phase references, the Claude import file, HTML library architecture, abbreviated business, technical, plan, and decision documents, and a final answer naming every consulted or changed document.
